# Identidade visual — uso editorial no GitHub

A identidade do **Marketing Hub** comunica um projeto acessível, criativo e organizado. No GitHub, a marca deve ajudar a reconhecer o produto — nunca competir com as instruções de uso.

## Referências oficiais

- **Nome:** Marketing Hub (forma gráfica da logo: `marketinghub`).
- **Assinatura:** “Seu marketing, num lugar só.”
- **Cores fornecidas:** rosa `#FF4F8B`, escuro `#2B1720`, branco `#FFFFFF`, fundo claro `#FFF7FA`.
- **Tipografia indicada:** Poppins, quando disponível. Fontes não são redistribuídas aqui.
- **Origem:** artes fornecidas pelo responsável, criadas com apoio de IA sob sua direção e mantidas sem alterações de bytes. Ver [procedência](../assets/ASSET-PROVENANCE.md) e [licença própria](../BRAND-ASSETS-LICENSE.md).

## Regra para o README

1. **Uma assinatura visual na abertura.** Usar `assets/brand/marketinghub-horizontal-fundo-rosa.png` como imagem principal, com largura de apresentação de aproximadamente 620 px. O arquivo tem fundo sólido, evita texto escuro invisível no GitHub em modo escuro e não exige edição.
2. **Não repetir a logo no corpo ou no rodapé.** Variações rosa, escura, vertical e transparente são recursos de produção, não itens para mostrar lado a lado num README de apresentação.
3. **Não usar a prancha `previa-marca.png` como demonstração do produto.** Ela reúne variações da identidade, não funcionalidades; incluí-la no fluxo de instalação confunde a mensagem.
4. **Priorizar produto e ação:** o visitante deve identificar o problema resolvido, testar sem instalar, entender o que recebe, saber os limites e encontrar ajuda.
5. **Acessibilidade:** sempre usar texto alternativo informativo; não depender da cor para comunicar estado; conferir o resultado nos temas claro e escuro e em tela estreita.
6. **Manter proporção e respiro:** não esticar, recortar arbitrariamente, recolorir ou aplicar sombras/efeitos às artes aprovadas.
7. **Evitar números promocionais sem evidência:** testes de código e fixtures sintéticas não são provas de superioridade editorial, compatibilidade universal ou ganho comercial.

| Social preview do GitHub | Uma imagem com fundo sólido, legível e aprovada para essa finalidade; configurar no GitHub |

## Prévia social e limitações do repositório

A **prévia social do repositório** é uma configuração independente do README e das metatags em `docs/index.html`. Substituir imagens no código não remove automaticamente uma prévia antiga escolhida em *Settings → Social preview*.

O banner e a prévia social antigos permanecem **retirados de divulgação** e estão identificados no [arquivo histórico](../assets/archive/v2.3.0/README.md). Não reutilizar como banner público nem afirmar compatibilidade ou benefícios ainda não demonstrados.

A identidade não é licenciada pela licença MIT do código. Qualquer nova peça promocional deve respeitar os [termos das artes](../BRAND-ASSETS-LICENSE.md) e a aprovação do responsável.
